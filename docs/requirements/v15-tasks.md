# 任务工作台 V1.5｜Codex 可执行开发任务清单

> **文档版本**：V1.5-Codex-Tasks / 2026-10-24  
> **依据**：用户确认的 V1.5 十项修订 +《任务工作台 V1.4 完整项目设计方案》（2026-10-23，50 页）  
> **性质**：开发执行清单，不等同于已完成代码、已通过的测试或已修改的 V1.4 原文件。  
> **执行策略**：依赖顺序推进，保留 V1.4「P0 / P1 / P2 优先级管理、不人为拆产品发布阶段」约定；每个任务可作为一条独立 Codex 工单。

## 0. 项目边界（Codex 必须遵守）

1. **产品定位不变**：「布置即分配」国企集团/子公司/部门任务工作台，主链路为 **领导布置 → 职能规则建议 → 领导确认 → 主办/协办部门执行 → 成果汇总 → 验收 → 统计/考核**。
2. **沿用已确认业务原则**：集团/子公司多主体；主办部门恰好 1 个、协办 0–2 个；跨公司协办须确认；标签规则仅辅助建议，领导最终确认；逾期后允许继续提交且历史事实可追溯；部门考核月度计算、7 天异议期、个人考核默认关闭、不直接与薪资挂钩。
3. **沿用 V1.4 已确认非本次修订的边界**：不做 OA 通用审批平台、公文流、薪资核算、考勤打卡；不强制添加外部 AI；业务数据和附件存放于公司自有环境；优先内网部署；完整 BPMN 引擎、微服务、Kubernetes、消息中间件、Redis 不是本次必选组件。
4. **开源策略**：参考 RuoYi-Vue3 / 配套后端的用户、部门、权限菜单、字典、日志、CRUD 设计；**业务核心自研**；不得整体复制若依认证体系或无审查地引入 JWT/Redis；复制任何代码前记录许可证、版本、来源与版权声明；遵守许可证义务。
5. **升级原则**：不假设仓库为空。先检查目录、已有实现、数据库迁移与 Git 状态；已有功能只做兼容性重构，禁止直接删除历史数据、覆盖生产配置或改变已发布 Flyway 迁移。没有代码仓库时，任务应可用于新建项目。
6. **安全首要规则**：前端隐藏按钮不是权限控制；所有读写、附件、导出、考核、查询都必须由服务端做角色、组织作用域、对象关系和状态合法性检查；不得将密码、TOTP 密钥、Cookie、Webhook、敏感附件正文写入日志。
7. **保持可解释性和可复核性**：任务分配要保存规则版本和命中理由；考核保留输入、版本、计算明细、人工调整和最终分数；禁止静默重算覆盖历史。
8. **禁止无证据完成**：Codex 只能报告自己实际运行过的构建和测试结果；依赖缺失/无运行环境必须标为“未验证”，不可称“通过”。

### 0.1 技术候选版本（须通过实际兼容验证后冻结）

| 组件 | V1.4 | V1.5 候选与边界 |
|---|---|---|
| 前端 | Vue 3、Vuex、Node 22.23.4 | Vue 3 + TypeScript + **Pinia** + Vite + Element Plus + Axios；Node 24 LTS 优先评估，若选 Node 22 须记录维护期 |
| Java | JDK 21.0.2 | **Java 21 LTS 的受安全维护补丁版本**，开发/CI/生产保持一致主版本 |
| Spring Boot | 3.3 | 比较 **4.1.x** 与 **3.5.x** 的安全维护和依赖适配；兼容性优先，最终精确版本写入 ADR 与锁定清单 |
| MyBatis | MyBatis | Spring Boot 4 对应 MyBatis Spring Boot Starter 4.x；Boot 3.5 对应 Starter 3.x（以官方兼容矩阵为准） |
| MySQL | 8.0.45 | MySQL **8.4 LTS**；生产小版本按安全补丁与变更审批更新 |
| 其他 | Spring Security、Flyway、MyBatis、Maven、Nginx | 保留；实现服务端 Session + CSRF，不默认改 JWT；保持模块化单体 |

**不能凭文档代替兼容性测试。** 初始评估两个可运行组合：Boot 4.1.x + Starter 4.x；Boot 3.5.x + Starter 3.x。先选出可构建、可迁移、认证可用的组合，再冻结 Maven BOM、JDK、Node、npm lockfile、MySQL 版本。MySQL 8.4 的具体补丁版本由部署日前安全公告确定。

**权重决策门槛**：V1.4 原默认 KPI 五指标及其 30/25/20/10/15 权重保持为“兼容模板”；V1.5 必须修正公式/样例并评估相关性，但**不能未经业务批准直接改正式考核权重**。候选新模板可先模拟计算，不得自动覆盖历史得分。

### 0.2 交付约定

- 每个任务包括：编号、优先级、依赖、实现范围、验收与测试、预期产出。
- 推荐每个任务单独提交 commit/PR；每个 PR 附迁移脚本、必要测试和变更说明。
- **代码命名、目录结构以实际仓库为准**。本文建议的 `backend/`、`frontend/`、`docs/`、`deploy/` 仅为参考，不得为迎合名称强行重排已有仓库。
- 只追加新的 Flyway `V...__...sql`；旧迁移禁止修改。现有业务数据先备份，再做兼容迁移。
- 所有修改的业务接口给出 API 请求/响应契约（含错误码）；高危写操作必须有权限和并发测试。

7. 若遇到尚未业务确认的考核权重、正式保留期、权限例外、附件扩展名等政策差异，保留 V1.4 当前有效行为，生成待确认 ADR；不擅自变更正式规则。

完成后按格式汇报：
A. 已完成/未完成内容；B. 修改文件清单；C. 新增/变更 API、表与索引；D. 实际执行的命令及结果；E. 安全与兼容检查；F. 迁移、回滚及风险；G. 下一任务依赖。

## 2. Codex 任务清单（42 项）

### A. 基线、技术栈、框架与契约

#### [ ] CDEX-001｜仓库现状审计与 V1.4 基线映射
- **优先级**：P0；**依赖**：无。
- **实施**：盘点仓库前后端模块、现存表/迁移、登录模式、权限入口、已完成功能；根据 V1.4 50 页建立功能对照矩阵，区分“已实现/部分实现/未实现/冲突/未验证”。
- **验收**：不得假设仓库为空；标记状态机、考核、附件、跨公司、通知相关缺口及影响范围；不可修改业务代码。
- **产物**：`docs/audit/v14-gap-analysis.md`、`docs/adr/README.md`；记录编译/测试可运行条件。

#### [ ] CDEX-002｜技术版本兼容性 PoC 与技术选型 ADR
- **优先级**：P0；**依赖**：001。
- **实施**：分别验证 Boot 4.1.x + MyBatis Starter 4.x、Boot 3.5.x + Starter 3.x 在 Java 21 下的 Spring Security Session/CSRF、Flyway、MySQL 8.4、JSON API、Actuator；前端验证 Vue 3 + TypeScript + Pinia + Element Plus + Vite 在 Node 24 LTS 与现有构建链上可用。
- **验收**：至少一组组合完成启动、建库迁移、登录会话、CSRF 写操作与简单 Mapper 集成测试；记录不能通过的组合、原因、版本和决策依据，不得以“最新”作为唯一依据。
- **产物**：`docs/adr/ADR-001-tech-stack.md`、精确版本清单、PoC 测试结果。

#### [ ] CDEX-003｜前后端工程与质量门禁
- **优先级**：P0；**依赖**：002。
- **实施**：建立或调整模块化单体工程、环境配置分层、TypeScript 类型检查、ESLint、Java 静态检查、测试任务、CI；加入 npm lockfile 与 Maven 依赖管理。
- **验收**：干净环境可按 README 启动；`npm ci`、类型检查、前端构建、`mvn test` 可按项目脚本执行；敏感配置来自环境变量或受控密钥而不是代码库。
- **产物**：工程结构、`.env.example`（不含真实秘钥）、`docs/development.md`、CI 配置。

#### [ ] CDEX-004｜API 契约与错误码统一
- **优先级**：P0；**依赖**：003。
- **实施**：对齐 V1.4 第 34–36 页 `/api/v1` 接口，统一 `code/message/data/traceId` 与分页对象；定义 400/401/403/404/409/422/429、业务错误码与字段校验格式；整理 OpenAPI 草案。
- **验收**：不返回 Java 堆栈；列表排序字段白名单；前端与服务端共享 API 类型或生成策略；带参数/权限错误用例。
- **产物**：`docs/api/openapi.yaml`（或等效生成文件）、错误码规范、契约测试。

### B. 组织架构、数据权限与数据库

#### [ ] CDEX-005｜原 19 表字段一致性与迁移审计
- **优先级**：P0；**依赖**：001、002。
- **实施**：核对 `sub_task.accepted_at` 与考核 SQL 中 `received_at`、缺失的 `sub_task.created_at`，以及 `notification.read_at/sent_at` 与索引字段 `is_read/created_at` 的冲突；核对任务状态枚举、附件类型和字段命名。
- **验收**：确定唯一规范字段，形成映射表、兼容迁移与查询修订；MySQL 8.4 Flyway 校验成功；老数据不丢失。
- **产物**：字段字典、只追加 Flyway 迁移、迁移前后验证 SQL。

#### [ ] CDEX-006｜新增缺失业务实体
- **优先级**：P0；**依赖**：005。
- **实施**：实现并建表：`task_comment`（留言、@提及）、`task_progress`（进度历史）、`task_deadline_request`（延期申请审批）、`collaboration_request`（跨公司协办确认）、`kpi_appeal`（独立申诉工作流），为通知投递和后台调度预留执行记录实体。
- **验收**：每表包含主键、必要外键或业务一致性约束、审计字段、状态枚举、索引；明确删除/归档行为；测试 CRUD 与非法跨公司引用。
- **产物**：Flyway SQL、Mapper、实体/DTO、数据库关系图、迁移测试。

#### [ ] CDEX-007｜一人多角色与跨公司组织关联
- **优先级**：P0；**依赖**：005。
- **实施**：由 `user.role` 单值扩展为 `role`、`permission`、`role_permission`、`user_role_scope`（或等价模型）；支持同一人员在多公司/多部门任职、有效期、主职/兼职、停用；保留历史责任归属。
- **验收**：旧单角色用户迁移后行为不变；同一账号可按授权选择组织上下文；不能凭客户端传入 company_id 扩权；同一人员不同岗位的权限不可错误合并。
- **产物**：数据迁移、授权模型说明、组织切换 API、集成测试。

#### [ ] CDEX-008｜资源级数据权限授权服务
- **优先级**：P0；**依赖**：007。
- **实施**：建立授权判断模型 `操作许可 ∩ 公司/部门作用域 ∩ 资源归属/参与关系 ∩ 任务状态条件`，在 Service 层统一使用；MyBatis 查询作用域必须服务端推导，严禁信任客户端 company_id/dept_id。
- **验收**：覆盖主任务、子任务、附件、留言、时间线、导出、排名和考核结果；A 公司员工不能通过猜 ID 获得 B 公司数据；跨公司协办只暴露经确认的必要内容；管理员默认只有运维/配置权限，例外访问须显式授权。
- **产物**：权限决策服务、授权规则矩阵、负向集成测试和安全审计事件。

#### [ ] CDEX-009｜负责人代理、调岗离职与转交
- **优先级**：P1；**依赖**：007、008。
- **实施**：设计代理授权（代理人、权限、时间窗、委托人）、岗位变更、离职停用、批量转交、任务原责任人快照，防止历史任务归属随着组织调整被覆盖。
- **验收**：已停用账号立即失去访问权限；在办任务可交接；过期代理自动失效；历史时间线、考核与审计不修改原归属；所有转交记录原因与操作人。
- **产物**：组织变动 API、代理表或等价实体、任务转交页面与测试。

#### [ ] CDEX-010｜数据库约束、索引与行版本
- **优先级**：P0；**依赖**：005–008。
- **实施**：完善唯一约束、外键、逻辑删除与历史引用规则；明确 `company.code` 唯一、主任务同部门不可重复子任务、主办唯一性；给 `task/sub_task` 增加 `version`；加入已授权公司范围下的查询索引。
- **验收**：并发分派不能生成重复单据；非法跨公司关系写入被阻止；EXPLAIN 验证关键分页 SQL；不得直接拼接用户输入的 ORDER BY；兼容 MySQL 8.4。
- **产物**：追加迁移、索引说明、约束负例和并发测试。

### C. 认证、会话、附件、审计与安全

#### [ ] CDEX-011｜服务端 Session、CSRF、密码与会话撤销
- **优先级**：P0；**依赖**：004、008。
- **实施**：保留工号+密码、BCrypt、首次登录改密、5 次失败锁 30 分钟与 8 小时无操作过期；Cookie 设 HttpOnly/Secure/SameSite；启用 Spring Security CSRF、登录后会话 ID 轮换；改密、重置、停用、权限变更后撤销关联会话。
- **验收**：未登录返回 401、已登录无权返回 403；缺失/错误 CSRF 的状态变更被阻止；退出和改密后旧 Cookie 无法继续访问；登录失败提示不泄露账号存在与否；部署环境强制 HTTPS。
- **产物**：安全配置、会话存取/撤销机制、认证测试。

#### [ ] CDEX-012｜TOTP 双因素认证与敏感操作复核
- **优先级**：P0；**依赖**：011。
- **实施**：为领导和管理员提供强制 TOTP 绑定/校验，其他角色可按公司策略启用；首次绑定需要当前口令或重新认证；密钥加密存储于服务端，密钥材料与业务库分离；提供一次性恢复码（仅保存哈希）、解绑审批、换机恢复和失败限速。
- **验收**：未经 TOTP 不能完成受保护登录；恢复码用后失效；TOTP 验证存在时间漂移窗口且不能在同一认证上下文重复接受验证码；重置安全留痕；调整考核/重置密码/临时授权等敏感操作要求近期重新验证。
- **产物**：绑定/校验/恢复 API、界面、安全测试及运维恢复流程。

#### [ ] CDEX-013｜Nginx HTTPS 与应用安全响应头
- **优先级**：P0；**依赖**：003、011。
- **实施**：生产环境 HTTPS、HTTP 跳转、TLS 配置、反向代理可信头白名单、HSTS（域名与证书确认后启用）、CSP、X-Content-Type-Options、Referrer-Policy、frame-ancestors；限制上传大小与超时。
- **验收**：生产场景禁止明文传登录信息；Cookie 只能随 HTTPS 发送；API 与静态资源同源；非法 Host/转发头不能影响 URL 与认证；WebSocket/微信内访问若使用必须验证对应行为。
- **产物**：`deploy/nginx/` 配置样例、TLS 部署清单、HTTP 安全检查脚本。

#### [ ] CDEX-014｜附件上传、下载、预览与导出安全
- **优先级**：P0；**依赖**：006、008、013。
- **实施**：文件存储在非 Web 根目录；随机存储名；扩展名/MIME/魔数/大小联合校验；禁止脚本与可执行文件；杀毒扫描或隔离队列；ZIP 防炸弹和路径穿越；下载/预览每次重新鉴权；安全 Content-Disposition；服务端导出 Excel 强制转义潜在公式单元格；水印附导出人/时间。
- **验收**：越权文件 ID 返回拒绝；木马与不合法格式无法直接公开；文件扫描失败不能直接进入可下载状态；可审计下载；ZIP 解压限制有效；导出 `= + - @` 等公式风险输入为纯文本。
- **产物**：附件服务、安全扫描适配、下载审计、攻击样例测试。**待确认 ADR**：V1.4 白名单与页面示例中 `.xlsx` 存在不一致，未确认前不要静默扩大可执行/文档格式白名单。

#### [ ] CDEX-017｜统一主/子任务状态机与逾期事实

## 7. 最终交付定义（Definition of Done）

当且仅当下列条件同时满足，才可将“任务工作台 V1.5”记为正式达到**已确认的修订目标**：

- [ ] CDEX-001～042 中所有适用的 P0 任务有代码/文档证据，且不存在未修复的阻断问题。

- [ ] V1.4 未被明确修订的业务边界、权限、视觉规则、主办/协办数量和考核管理政策保持兼容。
- [ ] 核心业务从“布置→匹配→确认→接收→分派→提交→汇总→验收→考核”端到端可运行。
- [ ] 跨公司数据隔离、TOTP、CSRF、附件、导出、审计、并发、幂等和通知可靠性经负向测试验证。
- [ ] MySQL 8.4 上新增 Flyway 迁移与历史兼容迁移完成测试；实际版本与锁定文件一致。
- [ ] 50 用户与性能指标完成环境化测试，未测项不得写“通过”。
- [ ] 数据库 + 附件完成隔离环境恢复演练，故障处置流程可执行。
- [ ] README、API 文档、配置样例、运维手册、许可清单和发布验收矩阵同步完成。
