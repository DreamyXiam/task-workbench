# 管理界面与权限一致性

用户要求修复统计分析、月度考核拒绝，优化岗位交接、日志字段与导出、角色权限界面，并参考 https://www.beautifului.dev/ 统一规范。

## 当前证据与方案

真实测试：全局管理员 stats/dept、kpi/runs、kpi/scores 返回403，领导均200。公司管理员有基础设施权限但无业务统计权限。采用服务端明确全局只读统计能力、前端按实际能力显示入口的方式；不改变公司管理员业务边界，不把全局管理员当作领导赋予人工调分等操作。相比仅隐藏入口，本方案修复全局管理员实际缺失的查看能力；相比全角色放行，保留公司、部门和业务操作限制。

日志通过专用查询服务返回明确camelCase字段、操作人与公司名称、对象类型、动作中文说明、时间、追踪号、代理标识。全局管理员及集团领导可查看全范围；其他领导和公司管理员限制本公司。支持关键词、时间与动作筛选、分页、详情与同筛选导出。导出保留近期验证、限流、大小限制和水印；不修改已有审计链，不暴露认证数据，不伪造历史变更内容。

权限配置保留现有只收紧功能的语义，返回角色支持功能；按任务、协作、管理分组，并显示实际生效与依赖关系、未保存提示、恢复和保存确认。全局管理员保持固定权限。

## 视觉和交互

沿用现有浅深色tokens、蓝色操作色、细边框和6至12px圆角。统一页面标题、筛选工具条、紧凑元信息行、状态标签与详情卡片。岗位页增加状态摘要、搜索和清晰的任职/代理/交接说明，保留现有业务表单。移动端单列，键盘可用，减少动态效果仍生效。不引入新组件依赖。

## 验收

全局管理员可读全范围统计/考核，公司管理员无新增业务数据访问；领导和部门负责人范围不扩大。日志分页、字段映射、筛选导出一致，越权和敏感内容测试通过。浏览器验证浅深色、375px和关键操作；正常PR检查、合并及部署，沿用服务器Java21.0.2/MySQL8.0.45并保留回滚。
