# V1.5 release checklist — not approved for production

All boxes begin unchecked. Local unit/build evidence is recorded in implementation reports and is not production acceptance. Release requires all applicable P0 tasks proven and P1 disposition explicitly accepted; security/isolation/restore failures cannot be waived by a build pass.

- [ ] ADR-001 online candidate compatibility complete; exact supported Boot/MyBatis/Flyway/driver/JDK21/Node/npm/MySQL8.4 patches frozen, current advisories checked, offline-verification excluded.
- [ ] All42 task rows in acceptance matrix have evidence; each incomplete P1 names impact, owner and accepted release scope. V1.4 mapping checked and13 original acceptance scenarios reconciled.
- [ ] Business baseline preserved: exactly one host,0–2 collaborators, explicit cross-company consent, original five weights30/25/20/10/15,7day appeals, personal KPI off, no payroll linkage.
- [ ] ADR-002–008 business decisions recorded where needed; proposed policy has never silently replaced effective rules.
- [ ] Clean Maven/npm CI, frontend lint/typecheck/tests/build, dependency lock, reproducible artifact SHA256, reviewed migration checksums and license inventory/SBOM.
- [ ] Gitleaks, Semgrep, Trivy, Dependency-Check and npm audit reports complete/current; no unresolved exploitable high/critical; branch protections/reviews configured; tool images/actions frozen by reviewed digest/SHA.
- [ ] A-01–A-07/B-01–B-05/K-01–K-04/O-01–O-03 negative/concurrent/security tests pass in intended stack.
- [ ] MySQL8.4 blank/historical migration and least-privilege denial tests; measured50user p95<1s APIs and submission<2s with data/hardware/method stated.
- [ ] Chrome/Edge and WeChat real-device login/CSRF/download;375/390/768/1024/1440 layouts, keyboard/focus/contrast and screen-reader checks.
- [ ] Linux clean-host deployment, valid HTTPS/Host/forwarded-header tests, cookies/headers/limits, quarantined-file denial and private Actuator verified.
- [ ] Root0600 secrets, external TOTP key/rotation, no canned initial credentials, audited bootstrap/password/TOTP enrollment and session revocation.
- [ ] Consistent encrypted DB+attachments base, off-host copy, continuous binlog+immutable-object archives, isolated point-in-time restore and checksum/business/KPI/outbox reconciliation; approved RPO/RTO measured.
- [ ] Metrics/alert/failure drills, audit integrity/off-host retention and backup failure/expiry alerts; approved ADR-005 policies represented.
- [ ] Reviewed rollback with schema compatibility/restoration; maintenance window and owner; no destructive automatic migration rollback.
- [ ] User/admin/operator handbooks, API/status/data dictionaries, permission matrix, known issues, artifact inventory and support ownership handed over.
- [ ] Pilot limited to1–2 departments and one monthly KPI cycle; issues triaged and user acceptance signed before wider rollout.

Release manifest: commit/release ID; JAR/frontend hashes; exact dependency/runtime/OS versions; SBOM/license report; migration versions+checksums; configuration names (no secrets); test/security/restore reports; known issue and P1 disposition; backup batch/binlog/object archive checkpoints; rollback compatibility.

Sign-off template: business owner___; security___; operations___; testing___; release operator___; timestamp/timezone___; approved scope___; unresolved items and deadlines___; approval evidence___; pilot result___. A blank signature or pending test is not approval.
